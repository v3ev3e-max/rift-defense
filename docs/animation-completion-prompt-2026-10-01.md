# 전체 애니메이션 보완 및 잘림 검증 실행 프롬프트

## 목표
`docs/animation-inventory-2026-10-01.md`와 현행 실제 렌더러를 기준으로 모든 누락을 보완한다. 단일 이미지 확대/회전/페이드를 전용 프레임 제작 완료로 간주하지 않는다. 기존 사용자 변경, 세이브, 밸런스, 정지 대기를 보존한다. GitHub 배포는 이번 요청에 포함하지 않는다.

## 제작 범위
1. 공격형 영웅 26명: 무기·속성·스킬 설명에 맞는 개별 시전 및 명중 이펙트. 각 6프레임. 기존 탄환과 평타 이미지 복사 금지.
2. 영웅 44명: 전용 피격 3프레임 제작. 캠페인 사망 3프레임을 실제 레이드 사망 재생에도 연결. 대기는 전용 idle 첫 프레임만 고정한다.
3. 캠페인 적: 누락된 공격/발사 33개 정의, 전체 피격, 누락된 사망 18개 정의를 보완. visualId 별칭과 지역별 실제 경로를 확인하고, 지역별로 제작된 이미지를 실전 코드에 연결한다. 기존 공격이 있는 brute도 4지역 외의 경로 누락을 확인한다.
4. 캠페인 네임드/보스의 실제 고유 패턴·페이즈 이벤트에 맞는 준비/발동/회복 프레임을 연결한다. 실제 없는 게임 상태를 임의 추가하지 않는다.
5. 태양의 스핑크스·영겁의 군주: 전용 준비·패턴·사망과 발사→비행→착탄→폭발 탄환을 각각 새로 제작한다. 공격/idle 재사용 fallback을 제거한다.
6. 레이드 소환체 5종: 이동·공격·피격·사망 제작 및 실제 사건에 연결한다.
7. 레이드 영웅 기본 명중 시트의 미재생 문제를 수정한다. 파일 교체 후 첫 칸부터 마지막 칸까지 유한 재생하고 이전 비행 애니메이션이 덮어쓰지 않게 정리한다.
8. 버프/지속효과, 드론, 상태, 기타 단일 전투 효과를 조사해 필요한 전용 프레임을 제작한다. 범용 시스템 효과와 영웅 소유 효과를 구분하고 캐릭터 효과는 소유자별 자산으로 제작한다.
9. 중복 픽셀을 가진 엘리스·셀레스티아 스킬 프레임을 새로 제작한다. 다른 반복 프레임은 시작/복귀 의도인지 판정한다. 정지 idle의 복제 파일은 결함으로 취급하지 않는다.

## 이미지 생성 기준
- 기본 내장 이미지 생성 도구 사용. 원본은 art-source, 런타임은 public/assets 아래에 저장한다.
- 한 자산/동작별 독립 생성. 기존 캐릭터 디자인을 참고하고 무기·속성·역할 유지. 서포터는 회복·정화·보호 동작이며 적 공격 연출 금지.
- 실제 투명 배경, 고정 카메라, 동일 크기, 동일 앵커, 동일 축척. 몸동작은 바닥 앵커, 효과는 중심 앵커.
- 6프레임 시트는 3열×2행. 각 셀의 사방 12% 이상 투명 안전 여백. 무기·머리카락·광원·파편 모두 셀 안에 포함. 셀 경계 넘침/캐릭터 복제/이물 이미지 금지.
- 패킹은 기계적 분할·동일 축척·투명 여백 보존만 한다. 잘린 원본은 축소로 숨기지 말고 재생성한다. 프레임별 독립 확대/크롭 금지.

## 재생 규칙
idle 고정. 공격·스킬·피격·패턴·페이즈·사망은 사건 발생 때만 1회 재생. 고우선 상태 보존, 종료시 idle 복귀(사망 제외), 타이머와 RAF/WAAPI 정리. 발사점→비행→명중→피격 반응 연결. CSS 효과만으로 새 프레임을 대체하지 않는다.

## 검증과 완료 조건
1. 소유자/동작/파일/프레임 수/제작 출처/런타임 연결/픽셀 검사/브라우저 결과를 manifest로 추적한다. 미완료 자산을 완료로 보고하지 않는다.
2. 모든 PNG/WebP 디코딩, 예상 파일 존재, 빈 프레임, 동일 픽셀 중복, 평타와 스킬 복사, 다른 캐릭터 간 공용 해시를 검사한다. 의도된 idle/복귀만 근거를 기록해 예외 처리한다.
3. 원본 셀과 패킹 프레임 모두 알파 경계 검사. 안전 여백 최소 24px(256px 기준), 모든 프레임 동일 캔버스·축척·앵커. 별도 떨어진 구성 요소는 파편인지 이물인지 컨택트 시트로 사람이 판정한다.
4. PC 1440×900, 모바일 390×844/360×640, 가로 844×390, 낮은 높이, 회전에서 실제 캠페인·레이드 AUTO/수동 전 영웅과 적 사건 재생을 검사한다.
5. 스프라이트 이미지 전체 영역, 회전된 탄환, 최대 범위 효과가 전투 영역 안에 있도록 배치한다. DOM/canvas 밖 잘림·가로 스크롤·버튼 가림·프레임 점프·반복 idle 공격·지상 보스 부유를 검사한다. overflow:hidden으로 결함 숨기기 금지.
6. 스크린샷/컨택트 시트와 테스트 결과를 저장한다. 픽셀 테스트 성공을 실제 기기 테스트 성공이라고 표현하지 않는다. 실제 기기가 없으면 에뮬레이션 결과로 명시한다.
7. 단위·브라우저 테스트, 프로덕션 빌드, 기본 index.html과 오프라인 local-test/index.html 검증. 게임 수정 후 오프라인 실행본도 재생성한다.
8. 결과 보고: 신규 자산 수와 프레임 수, 실제 연결 상태, 대상별 남은 항목, 잘림 검사 결과, PC/모바일 증거, 테스트/빌드 결과. 모든 게이트 통과 전 전체 완료 선언 금지.
